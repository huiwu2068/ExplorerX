# FEAT-003：双面板文件浏览

## 1. 文档说明

### 1.1 目的与范围

定义类似 Double Commander 的左右双文件面板，同时保持 Explorer++ 现有标签页、命令、文件夹树、工具栏和窗口存储语义。首版只支持左右布局；每个面板有独立标签栏和目录，窗口级 UI 共享，所有依赖“当前目录”的命令作用于活动面板。

### 1.2 已有基础

代码库已经包含以下未完成骨架，实施时应扩展而不是重复创建：

- `Config::dualPane`
- `Feature::DualPane`
- `IDM_VIEW_DUAL_PANE` 菜单资源和勾选状态
- `MainWndSwitch.cpp` 中对 `dualPane` 的切换
- `BrowserPane` 和 `BrowserWindow::GetActivePane()` 抽象

当前 `Explorerplusplus` 仍只持有一个 `m_browserPane`，`InitializeTabs()` 只创建一套 `TabBacking`、`MainTabView` 和 `TabContainer`，`UpdateLayout()` 也按单面板布局。因此现有菜单切换并不会产生真实的第二面板。

## 2. 目标与非目标

### 2.1 目标

- 左右面板各自拥有独立标签栏、当前目录和历史记录。
- 鼠标或键盘焦点清晰决定活动面板。
- 地址栏、导航按钮、文件操作、Terminal 等窗口级命令作用于活动面板。
- 可拖动分隔条调整比例，并跨重启恢复。
- 关闭双面板时不丢失右侧标签页。
- 旧版单面板会话可以无损升级。
- Everything 搜索结果显示为活动面板中的独立标签页；从结果打开文件夹时在动作发生时的活动面板创建普通标签。

### 2.2 非目标

- 首版不支持上下布局或超过两个文件面板。
- 首版不模仿 Double Commander 的全部快捷键、底部命令栏或插件系统。
- 不改变标准 F5 刷新、F6 焦点导航等既有快捷键。
- 不在首版实现跨面板目录同步、路径锁定或差异比较。
- 不允许一个标签页同时被两个面板拥有。

## 3. 用户体验

### 3.1 开启

用户通过现有“视图 > 双面板”菜单开启：

1. 保留当前面板为左面板。
2. 创建右面板及其独立标签栏。
3. 若当前会话有可恢复的右面板数据，则恢复；否则在右面板创建一个标签，其目录与开启前活动标签相同。
4. 左面板保持活动，除非恢复数据明确保存右面板为活动面板。
5. 默认分隔比例为 50:50；若有保存比例则恢复。

### 3.2 活动面板

- 点击文件列表、标签栏、面板空白区或让其子控件获得键盘焦点，都将该面板设为活动。
- 活动面板显示明确但不过度突出的主题色边框/标题强调；不能只依靠颜色，焦点矩形和辅助功能状态也要更新。
- 新增“切换到另一面板”命令；建议快捷键在实现阶段经冲突检查后选择，不能覆盖现有快捷键。
- 当焦点位于地址栏、工具栏或 Everything 结果标签时，该标签所属文件面板是命令目标。

### 3.3 共享 UI 的目标规则

| 功能 | 双面板行为 |
|---|---|
| 地址栏 | 显示活动标签路径；提交后导航活动标签 |
| 后退/前进/向上/刷新 | 作用于活动面板的活动标签 |
| 新标签页 | 在活动面板创建 |
| 关闭标签页 | 关闭活动面板的活动标签 |
| 文件夹树 | 跟随活动标签；树中导航作用于活动面板 |
| 状态栏 | 显示活动面板的选中项和目录状态 |
| Windows Terminal | 在活动面板当前目录启动 |
| Everything 结果 | 激活时在当前活动面板新标签中导航 |
| 任务栏标签缩略图 | 覆盖两个面板的所有标签；选中缩略图时先激活所属面板 |

任何命令都应在执行瞬间解析活动面板，不长期缓存裸 `BrowserPane*`。

### 3.4 跨面板文件操作

首版新增上下文菜单或“编辑”菜单命令：

- “复制到另一面板”
- “移动到另一面板”

目标目录是另一面板活动标签的当前目录。命令启用前必须确认源选择有效、目标为可写文件系统文件夹且源/目标不是同一 Shell 项。实际复制/移动继续走 Explorer++ 现有文件操作机制，以保留冲突提示、撤销和错误处理。

首版不抢占 Double Commander 常见的 F5/F6 快捷键，避免破坏 Explorer++ 既有 Windows 风格操作；快捷键映射另行设计。

### 3.5 关闭与标签合并

关闭双面板时不能静默丢弃右面板标签：

1. 进入“面板迁移事务”，暂停活动标签通知和空面板自动关闭逻辑。
2. 按右面板标签顺序，把其标签追加到左面板。
3. 不按路径去重；两个相同路径的标签仍被保留，因为它们可能具有不同历史、视图和选择状态。
4. 如果关闭前右面板为活动面板，其活动标签迁移后成为左面板活动标签。
5. 迁移成功后销毁右面板和分隔条，并退出迁移事务。
6. 任一标签迁移失败时停止关闭、保留双面板，并报告错误；不留下部分销毁状态。

优先实现真正的标签所有权转移。如果现有 `Tab`/ShellBrowser 生命周期不支持安全 reparent，可通过完整 `TabStorageData` 重建；重建方案必须恢复导航历史、视图模式、列、排序、锁定状态和选择状态，不能只恢复路径。

## 4. 架构设计

### 4.1 所有权模型

建议引入稳定的 `BrowserPaneId`（`Left`、`Right`）并将面板集合集中管理：

```text
Explorerplusplus
└─ BrowserPaneHost
   ├─ BrowserPane(Left)
   │  ├─ TabBacking
   │  ├─ MainTabView
   │  └─ TabContainer ── Tab/ShellBrowser...
   ├─ Splitter
   └─ BrowserPane(Right, optional)
      ├─ TabBacking
      ├─ MainTabView
      └─ TabContainer ── Tab/ShellBrowser...
```

`BrowserPane` 应拥有形成一套面板所需的 backing、tab view 和 tab container，避免这些对象一部分在窗口类、一部分在面板类而产生销毁顺序问题。

窗口保存 `activePaneId`，并提供：

- `GetActivePane()`
- `GetPane(BrowserPaneId)`
- `GetAllPanes()`
- `SetActivePane(BrowserPaneId, ActivationReason)`
- `GetOtherPane(BrowserPaneId)`

不得把数组/vector 地址当作长期身份；事件和存储都使用 `BrowserPaneId`。

### 4.2 活动面板切换事务

`SetActivePane` 是唯一切换入口，并按以下顺序更新：

1. 验证目标面板仍存在。
2. 更新 `activePaneId`。
3. 更新左右面板活动视觉与辅助功能状态。
4. 把地址栏、导航按钮、工具栏启用状态和状态栏切到目标活动标签。
5. 按现有配置同步文件夹树。
6. 发布一次 `ActivePaneChanged` 事件。

订阅者不得在事件回调中再次无条件设置活动面板。切换期间使用重入保护，并把重复切换合并为最后一个有效目标。

### 4.3 事件作用域

现有以浏览器窗口为范围的标签事件需要携带 `BrowserPaneId` 或能从 `TabContainer` 稳定反查所属面板。至少覆盖：

- 标签创建、选择、移动、关闭。
- ShellBrowser 导航开始/完成。
- 文件列表焦点和选择变化。
- 任务栏缩略图激活。
- 地址栏和文件夹树同步。

跨面板移动标签时，事件顺序定义为“源移除完成 → 所有者更新 → 目标插入 → 目标选择”，任何观察者都不应看到一个标签同时属于两个面板。

### 4.4 布局与分隔条

- `BrowserPaneHost` 在现有中央文件工作区内部布局左右面板。
- 分隔条支持鼠标拖动、键盘微调和双击恢复 50:50。
- 保存的是内容区域比例，不是像素。建议合法范围 `[0.20, 0.80]`。
- 每个面板最小宽度 240 DIP；窗口过窄时实际比例可以临时偏离保存比例，但不覆盖用户首选值。
- DPI 或显示器变化时，以 DIP 重算最小宽度和分隔条宽度。
- 单面板时不创建/不显示右面板和分隔条，左面板占满工作区。

布局优先级从高到低：窗口边框和固定工具栏、至少一个可用文件面板、双面板最小宽度、Display 等辅助窗格首选宽度。Everything 结果位于标签内容区，不参与横向宽度竞争。

### 4.5 存储模型与兼容

新增版本化模型：

```text
WindowStorageData
├─ dualPane: bool
├─ activePane: BrowserPaneId
├─ splitRatio: double
└─ panes[]
   └─ PaneStorageData
      ├─ paneId
      ├─ selectedTab
      └─ tabs[]
```

兼容规则：

- 新版本优先读取 `panes[]`；字段不存在时，把旧 `tabs` 和 `selectedTab` 映射为左面板。
- 过渡期写入新模型时，同时保留左面板的旧 `tabs` 镜像，使旧版本至少能恢复左面板。
- 未识别的 pane ID、非法比例和越界 selectedTab 使用安全默认值并记录非敏感诊断。
- 若 `dualPane=true` 但右面板数据缺失，按当前左侧活动目录创建一个右侧标签。
- 用户关闭双面板并完成标签合并后，保存为单面板状态，不保留隐藏的第二份标签副本。
- Feature Flag 关闭时仍能读取旧单面板数据；实验阶段不得因一次降级启动而覆盖并丢失尚未迁移的数据。必要时在 Flag 关闭的会话中禁止写回 v2 pane 数据。

XML 与注册表后端必须使用同一逻辑模型和同一默认值，并分别加入往返测试。

### 4.6 Feature Flag 发布策略

- 继续使用现有 `Feature::DualPane` 控制菜单可见性和功能创建。
- 第一阶段仅供开发/测试开启，收集崩溃、会话恢复和命令目标问题；该阶段已完成。
- 第二阶段默认启用 `Feature::DualPane`，普通启动即可在“视图 > 双面板”中切换。
- 后续稳定版本可移除已经不再承担灰度作用的 Feature Flag，但不得改变 `Config::dualPane` 的用户状态语义。
- `Config::dualPane` 表示用户窗口状态，`Feature::DualPane` 表示代码能力是否开放，两者不得混为一个开关。

## 5. 关键流程

### 5.1 在右面板执行窗口级命令

```text
右面板获得焦点
  → SetActivePane(Right)
  → 地址栏/工具栏刷新
  → 用户点击“向上”或 Terminal
  → 命令控制器在执行时 GetActivePane()
  → 只操作右面板活动标签
```

### 5.2 Everything 结果导航

```text
Everything 查询完成并显示结果
  → 用户随后激活左或右文件面板
  → 用户在结果中按 Enter
  → 控制器此刻读取 activePaneId
  → 在该面板创建标签并导航/选择
```

### 5.3 跨面板复制

```text
读取活动面板选择项
  → 读取另一面板活动目录
  → 验证目标能力和同项冲突
  → 交给现有文件操作服务
  → 两个面板按现有目录变化通知刷新
```

## 6. 异常与边界

| 情况 | 行为 |
|---|---|
| 右面板最后一个标签被关闭 | 按现有“最后标签”规则创建默认标签，不自动关闭整个窗口 |
| 活动右面板被功能关闭 | 先迁移标签，再把活动面板切为左侧 |
| 关闭时标签迁移失败 | 保持双面板和原有数据，报告错误 |
| 恢复数据只有右面板 | 将其规范化为左面板，避免空主面板 |
| 分隔比例损坏 | 使用 0.5 并在保存时修正 |
| 窗口极窄 | 优先折叠辅助窗格，再压缩两个面板 |
| 文件操作期间切换活动面板 | 已提交操作使用提交瞬间捕获的源/目标，不随焦点漂移 |
| 标签拖到另一面板 | 首版可不支持；若 UI 暴露拖放则必须执行完整所有权事务 |

## 8. 测试策略

### 8.1 单元测试

- 活动面板切换及重入保护。
- 面板比例约束和 DPI 换算。
- 旧单面板数据到新模型的迁移。
- XML、注册表的新模型往返。
- 非法 pane ID、比例、索引的安全回退。
- 关闭双面板时标签顺序、选择和完整状态迁移。
- 命令执行时而非排队时解析活动面板。

### 8.2 集成测试

- 开启/关闭双面板 100 次不泄漏窗口、标签或 ShellBrowser。
- 左右面板分别导航、开关标签、后退前进，状态互不串扰。
- 重启恢复两个面板、活动标签和分隔比例。
- 从旧配置启动可恢复全部旧标签。
- 地址栏、文件夹树、状态栏、任务栏缩略图跟随正确面板。
- Terminal 在正确面板目录打开。
- Everything 结果进入动作发生时的活动面板。
- 与底部/垂直 Display Window、文件夹树和窄窗口组合时布局正确。

### 8.3 手工可用性检查

- 仅用键盘可识别并切换左右面板。
- 高对比度和不同主题下活动面板明显。
- 100%、150%、200% DPI 下分隔条易于命中且无重叠。
- 屏幕阅读器能读出“左文件面板/右文件面板”和活动状态。

## 9. 验收标准

- 现有菜单能实际切换单/双面板，而不只是修改配置位。
- 两个面板拥有独立标签栏、目录、导航历史和选中状态。
- 共享命令始终只作用于执行时的活动面板。
- 用户可明确辨认活动面板，并能通过键盘切换。
- 分隔比例可拖动、受最小宽度约束并跨重启恢复。
- 关闭双面板后右侧所有标签按序保留，活动标签语义正确。
- 老版本单面板配置升级无标签丢失；过渡期旧版至少可读取左面板镜像。
- 两个面板间复制/移动使用另一面板当前目录，错误和取消不会破坏任一面板状态。
- 双面板、Everything 结果标签及现有 Display Window 同时开启时不重叠。
- Feature Flag 关闭时保持现有单面板行为，无功能回归。

## 10. 非功能要求

- 创建第二面板不复制全局服务或启动第二个主消息循环。
- 面板切换只更新必要 UI，不重新枚举未变化目录。
- 销毁顺序明确：停止面板事件 → 迁移/关闭标签 → 销毁标签 UI → 销毁分隔条和宿主。
- 日志可记录 pane ID、切换原因和迁移计数，但不记录完整用户路径。
- 新增类型使用 RAII 管理 HWND 关联对象和订阅生命周期。

- 是否在后续版本支持拖动标签跨面板。
- 是否增加上下布局和“交换左右面板”。
